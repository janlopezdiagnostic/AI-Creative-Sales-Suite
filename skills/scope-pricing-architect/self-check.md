# Self-Check

Run all 14 checks before any scope, price, or SOW leaves this skill. A check is pass or fail; there is no partial. Fix failures, or report them to the user by number. Never ship silently on a fail.

1. **Rates sourced.** Every rate, multiplier, and percentage in the output traces to a field in the studio rate sheet. Anything else reads [TO CONFIRM]. FAIL if any number appears from memory, from an example, or from a previous client.
2. **Deliverables counted.** The deliverables inventory lists quantities: SKUs, variants, formats, rounds. FAIL if any deliverable is described only in vague terms ("the range", "some adaptations").
3. **Pricing model stated.** The output names the model (fixed fee, day rate, retainer, paid discovery) and gives one line of reasoning. FAIL if the model is implied only.
4. **Tiers differ by scope, not rate.** Good, Better, Best use the same rates; differences are deliverables, rounds, timeline, or support. FAIL if any tier is the same scope at a lower rate.
5. **Good tier is honest.** The lowest tier is a scope the studio would happily deliver. FAIL if it is a straw man designed only to make Better look attractive.
6. **Revision caps present.** Included rounds are numbered per phase, a round is defined as one consolidated feedback set, and extra rounds are priced. FAIL if rounds are unlimited, undefined, or unpriced.
7. **Exclusions explicit.** Copy, photography, regulatory approval, print costs, and licences are each addressed as included, excluded, or available by change order. FAIL if any is silent.
8. **Source files addressed.** The output states whether native source files are included, excluded, or priced, and at what basis. FAIL if files are not mentioned.
9. **Usage and IP stated, flagged.** Usage scope (products, markets, media, duration where relevant) is written in plain language and the section carries the flag: "Drafting aid, have counsel review before use." FAIL if IP language appears without the flag.
10. **Kill fee present.** Cancellation terms exist with stages, and work completed is stated as payable. FAIL if cancellation is absent or a single flat term covers all stages with no reasoning given to the user.
11. **Payment schedule present and milestone tied.** Deposit before start, milestones tied to approvals, balance before final file release, invoice terms and late terms from the rate sheet. FAIL if payment is a single line ("payable on completion") or terms are invented.
12. **Change order rule present.** The output states that out of scope work is quoted and approved in writing before it starts, with price and schedule effect together. FAIL if changes are mentioned without the approval-before-work rule.
13. **Assumptions listed.** Every assumption the price rests on (SKU counts, client supplied assets, decision structure, timeline) appears under Assumptions. FAIL if a load bearing assumption exists only inside the estimator's head.
14. **No client send, no hidden content.** The output is a draft for the user, not a message to the client; nothing has been sent, posted, or written to any tool; no fees are hidden or buried; no other client's information appears anywhere. FAIL if any send happened, any fee is obscured, or any foreign client data is present.

## Reporting a failure

To the user, write: "Self-check fails: [numbers]." Then one line per failure stating what is missing and what input would fix it. Then wait. The user may fix the input, accept a [TO CONFIRM] marker, or instruct a different course, and that instruction is recorded in the output under Assumptions.

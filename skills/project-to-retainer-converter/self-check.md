# Self-Check: Project to Retainer Converter

Run every check before delivering any recap, map, proposal, or pitch kit. A failed check means: fix the output, or deliver it with the failure explicitly flagged to the user and the affected item withheld. Never silently ship a failed check. Report the result as "Self-check: 12 of 12 passed" or name the failures.

1. **Results claims sourced.** Every results claim in the recap carries a source and a date from the supplied evidence. Fail condition: any outcome stated without one, including any number that "everyone knows".
2. **Permission status recorded.** Every citable claim is marked permitted to cite (named), anonymised only, or internal only, and the output respects the strictest marking. Fail condition: a claim with no status, or an internal-only claim appearing in an external-facing draft.
3. **Failures faced.** If the project record shows lateness, errors, or dispute, the recap or plan addresses them before any success content, per Tree 1. Fail condition: a pitch-shaped output for a project whose record shows unresolved harm.
4. **Outcome gate run.** Tree 1's verdict (PITCH, PITCH SMALLER, REPAIR FIRST, WAIT) is stated in the output, and the output's shape matches it. Fail condition: a full retainer proposal under a REPAIR FIRST or PITCH SMALLER verdict.
5. **Expansion routes evidenced.** Every route used to size the retainer has evidence, an owner, and a trigger on the map. Speculation is marked as speculation and excluded from sizing. Fail condition: block days traceable to a route with no evidence.
6. **Priced only from the rate sheet.** Every rate, multiplier, and term in the proposal matches the studio rate and rules sheet, or is marked [TO CONFIRM]. No rate is borrowed from an example. Fail condition: any number that cannot be traced to the sheet.
7. **No rate discount.** The retainer rate equals the standard rate everywhere it appears. Regularity is answered with structure, never a cheaper rate. Fail condition: any "retainer rate", volume percentage, or loyalty reduction.
8. **No guaranteed outcomes.** The output promises capacity, continuity, and process only. Fail condition: any statement that the retainer will grow sales, win listings, or improve sell-through, in any softened wording.
9. **Structure consistent with the Scope template.** Block mechanics, overage, rollover rule, quarterly review with usage trigger, and exit match the Scope and Pricing Architect retainer scope template, or the difference is flagged to the user. Fail condition: a quiet contradiction (for example rollover promised here that the scope template does not carry).
10. **Exit stated plainly.** The proposal states the term, the notice, and what happens on exit, early enough that the client does not have to hunt for it. Fail condition: exit terms absent, or present only in a legal-flagged appendix.
11. **No silent writes.** Nothing has been sent to the client and no CRM, calendar, or file record has been changed without the user's confirmation of the exact text. Fail condition: any write described as already done that the user did not confirm.
12. **Mode declared and confidences separated.** The output declares Connected or Manual mode and what was actually seen, and separates verified facts from the studio's judgement and from speculation. Fail condition: mixed presentation where a reader cannot tell which is which, or another client's data used as this client's evidence.

# Self-Check

Run all 12 checks before any proposal, deck outline, credentials piece, or cover email leaves this skill. A check is pass or fail; there is no partial. Fix failures, or report them to the user by number. Never ship silently on a fail. Checks 1 and 2 are gates: a fail on either one stops the output regardless of the rest.

1. **No spec creative (gate).** The output contains no concepts, routes, mockups, renders, naming candidates, or designs of the client's actual product, and no imagery selected to pre-design the client's work. FAIL if any element designs this client's answer, whatever it is labelled (moodboard, thought starter, quick idea). PASS only if every creative element is the studio's past work, process evidence, or sourced category observation, or sits inside a confirmed paid phase per the alternatives ladder. An explicit user override, where one exists, is recorded under Assumptions.
2. **Prices match the scope output exactly (gate).** Every tier, total, rate, deposit, milestone, and term in the output matches the Scope and Pricing Architect output digit for digit. FAIL if any number is rounded, re-derived, improved, or carried from an earlier version, an example, or the user's memory. Any [TO CONFIRM] item open in the scope output appears as [TO CONFIRM] here too.
3. **Every claim is sourced.** Each factual or results claim traces to the case library (with citation permission), the discovery brief, or a client-supplied fact. FAIL if any outcome, award, client name, ranking, or capability is asserted without a source the user could produce on request.
4. **Case permissions respected.** Every case used sits within its library permission: named or anonymised as permitted, outcome cited only where permitted, imagery only where results language is not permitted. FAIL if permission was assumed from an old use rather than read from the entry for this use.
5. **Narrative arc served.** The document or outline follows the arc chosen for the deal type (playbook Part 2), opens with the client's problem rather than the studio's history, and each section or page advances the arc. FAIL if the structure is a template's default order with no arc decision behind it.
6. **Scope transcribed, not paraphrased.** Deliverables, quantities (SKUs, rounds, formats), exclusions, and assumptions match the scope output in substance and count. FAIL if a quantity changed in friendlier wording, or an exclusion present in the scope output is missing here.
7. **Exclusions visible.** What is not included appears in the proposal in plain language at body prominence, and in the deck outline on or beside the price page. FAIL if exclusions were dropped for elegance or moved to a footnote.
8. **Team truth.** Every person named will actually work on the project in the role stated; every credential line traces to the library or the person's record; no one is credited with another's work. FAIL if the team page is a recycled stock page or credits planned hires as staff.
9. **Timeline is real.** Dates are built backwards from the client's fixed points, include client-side obligations with owners, and contain no date the studio already knows it cannot meet. Rush, where the calendar requires it, appears priced from the scope output, not absorbed silently. FAIL if the timeline is the client's wish transcribed.
10. **Terms summary reconciles.** The terms summary matches the scope output line by line, is labelled a summary, states that the SOW governs, and carries the flag: "Drafting aid, have counsel review before use." FAIL if any term is softer here than in the scope output, or the flag is missing.
11. **One next step, dated.** The output ends with a single explicit next action for the client, with a date or window, and states what happens immediately after it. FAIL if the close is open-ended ("let us know your thoughts") or lists several competing asks.
12. **No send, no leakage, mode declared.** The output is a draft for the user; nothing has been sent, uploaded, or written to any tool; no other client's material appears outside a permitted library use; no internal margins, rate logic, or speaker-note commentary sits in a client-facing artefact; the mode (Connected or Manual) and what was actually seen are declared. FAIL if any send happened, any foreign client content appears, or internal notes are inside a file marked for the client.

## Reporting a failure

To the user, write: "Self-check fails: [numbers]." Then one line per failure stating what is wrong and what input or decision would fix it. For a gate failure (checks 1 or 2), lead with it and do not present the draft as usable until it is resolved or the user records an explicit override under Assumptions. Then wait. The user may fix the input, supply the missing source, or instruct a different course, and that instruction is recorded in the output under Assumptions.
